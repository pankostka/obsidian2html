# obsidian2html

> **This is a translation of [`README.cs.md`](README.cs.md), which is the source.** Changes are made there first and only then carried over here. Do not edit this file directly.  
> The exact rules and the reasons behind them are in [SPEC.cs.md](SPEC.cs.md) (Czech); the K and Z codes in brackets point there.

## What it is

This is an **HTML generator**.  
It is a Python script that you point at an **input directory of md files** (typically an Obsidian vault, but that is not required), and it writes the **HTML files** of a website into an **output directory**.  
The resulting site stands on its own and needs no database.  
It is made of **static pages with JavaScript**.  
They can be uploaded to a host, zipped up and sent by email, and so on.

I use it in two ways:
* **EVERYTHING EXCEPT** - everything is published except what I do not want.  
	I name such a directory or file so that it starts with an underscore.  
	Anything with an underscore, or inside a directory with an underscore, is ignored.  
	In other words: turn every `*.md` except `_*.md` into `*.html`.
* **ONLY WITH THE MARKER** - only what I want published is published.  
	I name such a file so that it ends with the character 🌐.  
	Turn every `*🌐.md` into `*.html` and ignore all other `*.md`.

I use everything-except for documentation and for a nicer view of md files.  
I use the marker for my personal site.  
My know-how lives in Obsidian: general articles, procedures, guides and the like.  
Some of those articles are general enough that I want them published.  
So I simply put 🌐 at the end of their names.

## Installation and running

Requires Python 3.11 or newer with markdown installed (`pip install markdown`).  
Invocation (the order of the switches does not matter):

```
python md2html.py --source C:\vault --dest C:\web --publish "*🌐.md"
python md2html.py --source C:\docs --dest C:\web-docs --publish "*.md"
```

The source directory becomes a website: a shared `styl.css`, images in an `img/` folder, a front page with cards and a tag filter, tag pages, search, a bar, a logo, RSS.  
`--source`, `--dest` and `--publish` are required; only with `--check` is `--dest` left out.  
`--publish` says which articles go out, and so picks one of the two ways from the introduction (K10).  
The site's own details - name, language and address - are not switches; they live in the vault in `config.toml` (K70).

| Switch              | What it is for                                                          |
| ------------------- | ----------------------------------------------------------------------- |
| `--source`          | the source directory with the `.md` files                               |
| `--dest`            | the destination directory the site is built into (Z50, Z55)             |
| `--keep-archives N` | how many recent archives of the previous output to keep, default 10 (Z55) |
| `--publish "pattern"` | what is published: `"*🌐.md"` only with the marker, `"*.md"` everything (K10) |
| `--check`           | only verifies that the site builds, writes nowhere. For a git hook      |
| `--if-changed`      | builds the site only when something changed since last time. For a scheduler (Z57) |

`--check` builds the whole site into a temporary directory, throws the result away and deletes the temporary directory.  
It returns `0` when the build passed and `1` when it did not, and prints the same notes as a normal build.  
It is meant for a git hook in the vault that checks before a commit that the site can be built, and stops the commit if not.  
It does not touch the destination directory, so it deletes and archives nothing (Z55).  
**`--check` together with `--dest` or `--keep-archives` is an error** - otherwise one might think something was written to the destination.

`--if-changed` is for a build run regularly, say every five minutes from a scheduler.  
When nothing in the source changed since the last build, it stops at once and leaves the destination alone, so the site is not rewritten for nothing.  
A new version of `md2html.py` counts as a change.

Exit code: `0` done, `1` conversion error, `2` bad arguments.

## Preparing the vault

- **What goes out** is set by `--publish`: either only the articles with the marker at the end of the name, or all of them (K10).
- **An underscore or a dot** at the start of a name excludes the folder or the file, in both modes (K20).
- **Templates** are skipped on their own; the folder is read from Obsidian's settings (K15).
- **The title** of an article is its file name without the marker; the frontmatter key `title` overrides it (K25).
- **The address** of an article is its file name without diacritics, in lower case and with hyphens, e.g. `obsidian-nastaveni.html` (K30).
- **The excerpt** on a card is the first paragraph of the article (K40).
- **Attachments** are looked up next to the article, in its `Attachments/` folder and finally anywhere in the vault (K50).
- **The thumbnail** of a card lies in `Attachments/` and is named like the article; the recommended size is 630x290 (K60).
- **The date** belongs in the frontmatter as `date: YYYY-MM-DD`; otherwise the file's date is used (K80).
- **The tag** `Obsidian/Video` is two tags, `Obsidian` and `Video` (K95).
- **A leading tag** is marked with an underscore, `_Obsidian`, and then leads the filter on the front page (K97).

The frontmatter keys are in English: `date`, `title`, `excerpt`, `slug`, `tags` (K90).

## Site settings

The site settings live in the vault in the `_obsidian2html/` folder, or `.obsidian2html/` when it should be hidden in Obsidian (K70).  
Both at once is an error.  
Everything in it is optional:

- `config.toml` - the name, language and address of the site, and the date filter.
- `index.md` - a hand-written introduction on the front page.
- `logo.svg` - the logo at the top left, a link to the front page.
- `menu.md` - the bar in the header, sets the order of the tags. Without it the order is alphabetical.
- `styl.css` - custom styles, appended after the generated ones (Z40).

`config.toml` is a text file in the [TOML](https://toml.io) format: `key = value` on each line, text in quotes, a comment after `#`.

```toml
name = "Pan Kostka"                 # the name of the site
lang = "cs"                         # the language of the site, cs or en
base_url = "https://pankostka.cz"   # the address of the site, no rss.xml without it
date_filter = true                  # a slider with a histogram on the front page
```

- `name` - the name of the site at the top left, in the title of every page and in RSS. The default is the name of the vault folder.
- `lang` - the language of the site's buttons and labels, not of the articles (K100). The default is `cs`.
- `base_url` - the address the site will run at. Without it no `rss.xml` is produced.
- `date_filter` - `true` adds a period slider under the tags on the front page, with a histogram of articles (Z75). By day, month or year, depending on how long a period the site covers. The default is `false`, written without quotes.

A missing key has its default; an unknown key or an invalid value stops the build.

## What the tool promises

- No dead link is produced: when the target is not on the site, the link is left as text and the build says how many (Z10).
- Examples in code blocks stay as written (Z20).
- A missing image stops the build; no site with a hole in it is produced (Z30).
- The vault is only ever read, never written to (Z45).
- Where output goes is decided by `--dest` alone (Z50).
- The destination is emptied before the build, entries starting with a dot stay, the previous content goes to an archive, and a foreign directory is never deleted (Z55).
- With `--if-changed`, a site where nothing changed is not built again (Z57).
- Attachments get lower-case ASCII addresses, so links work on a Linux server too (Z60).
- The tag filter survives a click into an article (Z70), and when a single article is left, it opens (Z80).
- The optional date filter combines with the tags, and its histogram shows the days, months or years without an article too (Z75).
- Below the footer of every page is the date and time the site's content last changed, not the build time (Z85).
